# Recipe (api sources)

{"version":1, "base_url":"https://...", "auth":{"type":"none|api_key{in,name,value}|bearer{token}|basic{username,password}|oauth2_client_credentials{token_url,client_id,client_secret,scope}|oauth2_refresh_token{...}|login{request{path,method,body},token_path,expires_in_path,apply{in,name,prefix}}"}, "request":{"method":"GET","path":"/x","query":{},"headers":{},"body":{},"records_path":"data.items","format":"json|csv"}, "pagination":{"type":"none|page{param,start,size_param,size,stop:empty|short_page|total,total_path}|offset{offset_param,limit_param,limit,stop}|cursor{param,cursor_path,has_more_path,on_missing:error|end}|next_url{next_path,on_missing:error|end}|link_header"}, "window":{"start_param","end_param","format","max_days","initial_days"}, "incremental":{"field","format","param","param_format","overlap_minutes"}, "detail":{"request":{...path with {{record.id}}},"concurrency"}, "error_when":[cond + "message_path"], "record_key":"id", "drop_fields":["fetched_at"]}

This is a summary; the source of truth for every field (detail.merge, add_fields, hmac prefix and body_sha256 and the rest) is https://business.gymrankx.com/docs/intelligence/api-recipes/schema.md, with the guide in https://business.gymrankx.com/docs/intelligence/api-recipes/v1.md.

Templates: {{secret.x}} {{token}} {{cursor}} {{page}} {{offset}} {{limit}} {{window.start}} {{window.end}} {{now}} {{record.path}} (detail only). {{cursor}} is the incremental "since" value saved from the last sync, not the pagination cursor: a cursor pagination sends its own value in pagination.param by itself.
Paths split on dots: a key that has dots goes in brackets and quotes, so OData's next link is the path ["@odata.nextLink"] (in JSON: "next_path":"[\"@odata.nextLink\"]").

More auth types (also valid in version 2): api_key with "rotate_header":"X-Next-Key" (the key changes on every response; needs concurrency 1); hmac {"secret":"{{secret.x}}","header":"X-Signature","timestamp_header":"X-Timestamp","timestamp_format":"unix_s|unix_ms|iso","algorithm":"sha256","encoding":"hex|base64","sign":["timestamp","method","path","body"] (path includes the query),"separator":"\n","headers":{"X-Key":"{{secret.key}}"}}; cookie_session {"page":{"path":"/login"} (GET that sets the first cookie and has the CSRF in the HTML), "csrf":{"from":"html|header|json","name":"csrf_token"} (used as {{csrf}} in the login body), "login":{"path":"/login","body_format":"form","body":{"usuario":"{{secret.u}}","senha":"{{secret.p}}","csrf_token":"{{csrf}}"}}, "session_csrf":{"from":"header","name":"X-CSRF-Token"} (token for the next calls, taken from the login response), "send_csrf":{"in":"header","name":"X-CSRF-Token"}, "required_cookie":"SESSIONID"}.

Formats: "format":"json|csv|xml|file". xml parses the body (SOAP too; namespace prefixes are removed, so records_path is like "Envelope.Body.ListarResponse.Itens.Item"); for SOAP send "body_format":"xml" with the whole envelope as a string in "body" and a "SOAPAction" header. file reads CSV/XLSX, ZIP (one or more files, "file":{"entries":"*.csv","encoding":"windows-1252","delimiter":";","sheet":"Aba"}) and GZIP; each row of a ZIP gets "_file". "base64_path":"data.arquivo" decodes a base64 field of a json/xml response and reads it as a file.

Pagination extras: cursor in a response header {"type":"cursor","param":"page_token","cursor_header":"X-Next-Page"}; GraphQL cursor in the POST body {"type":"cursor","in":"body","param":"variables.after","cursor_path":"data.x.pageInfo.endCursor","has_more_path":"data.x.pageInfo.hasNextPage"}; "on_missing":"end" only when the API omits the cursor_path or next_path field on the last page (nextPageToken, @odata.nextLink), otherwise a missing field is a recipe error (GraphQL errors come with HTTP 200: add error_when {"from":"errors","is":"not_empty","message_path":"errors[0].message"}). Rate limit per minute: "limits":{"rate_limit":{"requests":100,"per_seconds":60},"max_requests":20000}.

## Recipe in steps (version 2) for chained APIs
Use it when one list gives the ids for the next call (units, then employees, then time records), when ids come in batches, or for asynchronous exports. {"version":2, "base_url", "auth", "steps":[step...], "error_when", "record_key" (of the final records), "limits", "retry"}.
- Each step: {"name":"funcionarios" (snake_case), "title":"short Portuguese description", "request":{...same as above}, "pagination", "window", "concurrency":2, "emit":"records|context" (default: last step records, others context), "parent_as":"funcionario" (nests the parent record in each record), "add_fields":{"chave":"{{parent.id}}|{{record.data}}"}, "auth":"inherit|none", "drop_fields"}.
- Step N runs once per record of step N-1. In its templates use {{parent.path}} (the record of the previous step) and {{steps.<name>.path}} (any earlier step in the chain). {{record.path}} only in add_fields.
- Batches of ids: "batch":{"size":50,"path":"id","separator":","} and "query":{"ids":"{{batch}}"} (or "body_param":"ids" for a JSON array).
- Detail merged into the parent: "merge":{} (first record merged into the parent) or "merge":{"as":"afastamentos"} (all child records, all pages, as an array in the parent).
- Asynchronous export: {"type":"poll","request":{create, e.g. POST},"status":{"path":"/jobs/{{job.id}}"} (job = the create response after records_path),"done_when":[cond],"failed_when":[cond],"interval_ms":5000,"timeout_ms":600000,"window":{...}} outputs job+status merged; then {"type":"download","url":"{{parent.file_url}}","file":{"entries":"*.csv"}} reads the file.
- A child that fails for one parent does not stop the run: it is retried and stays pending for the next run. The probe of a version 2 recipe follows only 2 records per step and the first window; its "steps" list shows tasks, records, errors and a sample per step: fix the first step with errors.

Example (punches per employee): steps [{"name":"unidades","request":{"path":"/unidades","records_path":"unidades"}},{"name":"funcionarios","request":{"path":"/unidades/{{parent.codigo}}/funcionarios","records_path":"funcionarios"},"pagination":{"type":"page","param":"pagina","stop":"total","total_path":"total_paginas"}},{"name":"jornadas","request":{"path":"/funcionarios/{{parent.id}}/marcacoes","records_path":"jornadas"},"window":{"start_param":"inicio","end_param":"fim","format":"yyyy-MM-dd","max_days":31,"initial_days":150},"parent_as":"funcionario","add_fields":{"chave":"{{parent.id}}|{{record.data}}"}}], "record_key":"chave". The mapping then reads "funcionario.cpf".
